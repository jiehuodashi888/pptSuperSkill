# 仓库入口文档设计

## 意图

让第一次接触本仓库的企业内网使用者能在 GitHub 首页快速理解项目用途、隔离边界、安装方式、最小验证路径和实例化入口；同时为架构评审者提供独立、可引用的中英双语技术说明，而不把 README 扩展成设计文档副本。

## 已选方案与备选方案

| 方案 | 取舍 | 结论 |
| --- | --- | --- |
| 中文上手优先 README + 独立中英双语架构文档 | 首页简洁，使用者和架构读者各有明确入口 | 采用 |
| 架构优先 README | 便于评审，但增加首次运行门槛 | 不采用 |
| 单一中英双语 README | 覆盖面广，但篇幅大且维护成本更高 | 不采用 |

## 交付物

1. 根目录 `README.md`（中文）：项目定位、能力与边界、目录、安装与最小验证、示例实例、企业实例化流程、测试、链接和安全提示。
2. `docs/ARCHITECTURE.md`（中文后附 English）：核心与实例隔离、关键契约、九观察员、生成与 QA、能力降级、本地审批、扩展边界及文档索引。

## 约束

- 不承诺当前运行时尚未实现的模板填充、既有 PPT 编辑、云端多租户或真实企业样本学习能力。
- 所有命令必须与现有 `package.json` 脚本一致，并明确 Node.js 20+ 要求。
- 将企业数据仅定位在本地实例包；不把模板、样本或机密内容写进通用核心文档。
- README 链接现有 SKILL、详细设计和新架构文档，避免复制相互矛盾的规范。

## 验收

- 新读者可从 README 复制命令完成安装、类型检查、测试与示例实例校验。
- 架构读者可从独立文档理解核心/实例边界与能力降级，而不需要阅读源代码。
- 术语与当前实现、`SKILL.md`、设计文档保持一致。
